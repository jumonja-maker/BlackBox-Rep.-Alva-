# BLACK.BOX Universal

**РУССКИЙ** · [English / README.md](README.md)

**v0.3.0 — релиз-кандидат** · Портативная программа для Windows · Открытый монитор процессов · Внутренняя обработка диагностических данных

BLACK.BOX Universal позволяет **выбрать доступный процесс и наблюдать за ним**, не меняя исходный код программы и не устанавливая в неё агент. Приложение собирает системные показатели, сохраняет историю локально и создаёт понятные локальные отчёты для человека. При необходимости ими можно поделиться самостоятельно.

**Для обычного запуска Windows EXE не нужны Python, локальный ИИ, Git или PowerShell.** Обработка диагностических данных не требует отдельной вкладки или настройки Alva.

> **Статус выпуска:** v0.3.0 — кандидат в [Draft PR #7](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/pull/7), **а не опубликованный стабильный GitHub Release**. Изменения ещё не приняты в `main`. Автоматические тесты Windows/Linux и проверка запуска EXE прошли; ручная проверка обновления/удаления в Windows и испытание с настоящей закрытой Alva пока не завершены.

## Полноценный BLACK.BOX со встроенной Alva (планируемый выпуск)

Официальный Windows ZIP будет собираться владельцем из ЗАКРЫТОЙ Alva и
ОТКРЫТОГО BLACK.BOX. После нажатия «ОСТАНОВИТЬ» диагностические проверки
настоящей Alva выполняются **автоматически внутри BLACK.BOX**. Пользователю
не нужны отдельный Python, вкладка Alva, учётная запись или Интернет.

**Пока не опубликовано:** существующие артефакты публичного GitHub Actions
— тестовые сборки самостоятельного BLACK.BOX **без Alva**. Они подходят
для проверки обычных функций, но не являются полной версией со встроенной
платформой. Для первого полноценного выпуска необходимы проверенная
закрытая сборка Windows, испытание настоящей Alva и разрешение на
распространение её исполняемого Runtime. После этого ZIP появится в
[официальных Releases](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/releases).
См. [архитектуру полноценного выпуска](docs/REAL_ALVA_BUNDLED_RELEASE.md).

## Скачивание и запуск (Windows x64)

1. Открой [GitHub Actions](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/actions), найди **успешный** запуск *BLACK.BOX Universal - Shell QA and Windows portable* для этой версии и скачай артефакт `BLACK.BOX-Universal-Windows`. После официального выпуска загрузка будет доступна в [Releases](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/releases).
2. Распакуй **всю** папку `BLACK.BOX-Universal`. Не вынимай один EXE отдельно: ему нужны файлы из `_internal` и служебная программа обслуживания.
3. Запусти **`BLACK.BOX-Universal.exe`** двойным щелчком. Для наблюдения за обычными доступными процессами не нужно регистрироваться, открывать терминал или запускать приложение от администратора.
4. Внизу слева выбери **RU / ENG**. Язык переключается сразу и запоминается.

Программа **портативная**: не требует стандартного установщика Windows и не устанавливает фоновую службу. Системные и защищённые процессы могут быть недоступны без дополнительных прав.

## Возможности и разделы интерфейса

| Раздел | Что реально делает |
| --- | --- |
| **01 — Обзор / Overview** | Показывает выбранный процесс, загрузку **CPU %**, **RSS-память выбранного процесса**, количество целевого и видимых дочерних процессов, число измерений, график CPU/памяти, **Начать / Остановить** и последние сообщения наблюдателя. |
| **02 — Процессы / Processes** | Обновление списка процессов Windows, поиск по имени или PID, выбор строки и **Attach / Выбрать процесс**. Двойной щелчок тоже выбирает процесс. **Сам выбор не запускает запись.** |
| **03 — Журнал / Event Log** | Локальные события **самого наблюдателя BLACK.BOX**: выбор, начало/остановка, исчезновение цели, ошибки получения данных или хранилища. Это **не** внутренний лог чужой программы и не стек вызовов её ошибок. |
| **04 — Отчёты / Reports** | Просмотр текущего JSON-снимка, сохранение снимка по кнопке, **сравнение двух сохранённых сеансов**: число измерений, CPU, RSS, дочерние процессы, длительность. Разница показателей сама по себе не доказывает регрессию. |
| **05 — Настройки / Settings** | Интервал измерений **1 / 2 / 5 секунд**, включение/отключение проверки обновлений при запуске, создание ярлыка Windows, удаление портативной программы. |
| **Кнопки оболочки** | **GITHUB** открывает репозиторий, **E-MAIL** — письмо на `jumonjescu@mail.ru`, **RU / ENG** переключает язык, **Обновить / Check Updates** проверяет официальные GitHub Releases. |

### Какие данные собираются

Используется адаптер `psutil`, читающий доступные счётчики операционной системы. Каждое измерение может содержать:

- Время от начала сеанса, **загрузку CPU %** и **RSS-память выбранного основного процесса**.
- Количество потоков и **число дочерних процессов** (если Windows разрешает).
- Объём прочитанных/записанных байтов по **счётчикам I/O процесса** (если доступны).
- Коды сбоев наблюдения: `ACCESS_DENIED`, `PROCESS_EXITED`, `PID_REUSED`, `SAMPLE_UNAVAILABLE`, `STORAGE_ERROR` и другие.

График строится на **реальных измерениях**, а недоступные значения не выдумываются. В памяти интерфейса хранится ограниченная недавняя история, при этом измерения записываются в SQLite. **RSS на экране — память выбранного процесса, а не гарантированная сумма памяти всех дочерних процессов.**

## Как провести первое наблюдение

1. Открой **02 ПРОЦЕССЫ**, нажми **ОБНОВИТЬ СПИСОК**, найди программу по имени или PID и выбери строку.
2. Нажми **ВЫБРАТЬ ПРОЦЕСС / ATTACH** либо дважды щёлкни строку. BLACK.BOX проверит доступность процесса.
3. На странице **01 ОБЗОР** нажми **НАЧАТЬ НАБЛЮДЕНИЕ**. Создастся новая папка сеанса и база SQLite.
4. Пользуйся наблюдаемой программой как обычно. Смотри график и раздел **03 СОБЫТИЯ**.
5. Нажми **ОСТАНОВИТЬ**. BLACK.BOX завершит запись и автоматически создаст JSON и HTML-отчёт для человека.
6. Открой **04 ОТЧЁТЫ**, чтобы увидеть снимок данных, или нажми **СРАВНИТЬ СЕАНСЫ** и выбери две сохранённые папки.

Если программа закрылась, PID был повторно использован или Windows запретила доступ, BLACK.BOX отмечает проблему **наблюдения**, а не заявляет, будто нашёл настоящую причину ошибки приложения.

### Куда сохраняются сеансы и что внутри

Стандартная папка Windows:

`%USERPROFILE%\Documents\BLACK.BOX Universal\sessions\session-<уникальный-id>`

| Файл | Назначение |
| --- | --- |
| `session.sqlite3` | Последовательность измерений, сведения о сеансе, коды ошибок наблюдения (SQLite WAL). |
| `report.json` | Время начала/конца, статус сеанса, число измерений, максимальная RSS/CPU, дочерние процессы, ошибки наблюдателя. |
| `report.html` | Тот же итоговый отчёт в HTML для обычного браузера. |
| `alva-diagnostics.json` | **Внутренний инженерный отчёт:** формируется только при заранее разрешённой установке платформы, не доказывает первопричину ошибки наблюдаемой программы. |

Можно отдельно нажать **СОХРАНИТЬ JSON** на странице «Отчёты» и самостоятельно выбрать путь для снимка. В файлах могут быть имена процессов, PID или локальные пути — **проверь их перед отправкой другим людям**.

## Alva — закрытая платформа и дополнительная интеграция

BLACK.BOX Universal обладает **собственным открытым ядром**: сбор данных процесса, SQLite и базовые отчёты. Дополнительно предусмотрено подключение **Alva** — **отдельной закрытой Python-платформы** для разработки и структурированной диагностики: [jumonja-maker/Alva](https://github.com/jumonja-maker/Alva) (нужен доступ).

**Важно понимать различие:**

- В публичный BLACK.BOX и его Windows EXE **не входят исходники, wheel или сама библиотека закрытой Alva**. BLACK.BOX не устанавливает её незаметно.
- Пользователь с разрешённым доступом может установить Alva **отдельно**, в доверенное окружение Python **3.11+**. Без Alva работают наблюдение, отчёты и сравнение сеансов.
- Интеграция ориентируется на **предварительную (PREVIEW) версию API Alva** с инженерной привязкой к коммиту `a44297c5408628d9447bbf7db394b95ebd33fa20`. Наличие пакета или успешный ответ API **не подтверждают автоматически** исходный Git-коммит и право распространять библиотеку.

### Внутренний диагностический механизм (для сопровождающих)

В интерфейсе BLACK.BOX **нет отдельной вкладки Alva, кнопки подключения платформы или лаборатории**. Пользователь работает только с разделами «Обзор», «Процессы», «События», «Отчёты» и «Настройки». После остановки наблюдения программа автоматически создаёт стандартные отчёты без требования установить Alva.

Если сопровождающий ранее разрешил доверенное локальное Python-окружение с закрытой Alva, ограниченная проверка может запускаться **в фоне** при завершении сеанса, оставляя дополнительный `alva-diagnostics.json`. Публичная версия не скачивает и не включает Alva. Отсутствие платформы **не означает отказ BLACK.BOX**; обычные отчёты нельзя представлять как вывод самой Alva. Подробности: [контракт скрытого диагностического механизма](docs/INTERNAL_DIAGNOSTICS_NO_BRAND.md).

## Обновление, ярлык, удаление

**Обновление.** Кнопка **ОБНОВИТЬ / CHECK UPDATES** расположена сверху. Она становится **зелёной только при обнаружении официального более нового GitHub Release** с ожидаемым ZIP и проверяемой контрольной суммой SHA-256. Проверка при запуске включена по умолчанию; её можно отключить в настройках. Скачивание и установка требуют подтверждения. Служебный EXE проверяет архив, после завершения BLACK.BOX заменяет прежние файлы, переносит пользовательские данные и пытается удалить старую версию. **Артефакты GitHub Actions и Draft PR — не обновления.** Пока подходящий новый официальный Release не опубликован, зелёного индикатора не будет.

**Ярлык.** В **НАСТРОЙКАХ → СОЗДАТЬ ЯРЛЫК** формируется Windows `.lnk` со ссылкой на портативный EXE. Если Windows показывает стандартную иконку, это не влияет на функциональность программы.

**Удаление.** В **НАСТРОЙКАХ → УДАЛИТЬ ПРОГРАММУ** нужно подтвердить действие. Отдельный `BLACK.BOX-Maintenance.exe` дожидается закрытия главной программы, удаляет переносную папку, а находившиеся внутри неё `logs/`, `sessions/`, `reports/` предварительно переносит в сохранённую папку в «Документах». Уже существующие сеансы в стандартной папке «Документы» **не удаляются**. Это **удаление портативной папки**, не запись в системном списке «Установленные приложения». Ручные Windows-испытания обновления и удаления ещё ожидаются.

[Подробности обновления и удаления](docs/UPDATES_FEEDBACK_UNINSTALL.md)

## Запуск из исходников и CLI (для разработчиков)

Пользователь Windows с Python 3.11+ может дважды нажать `Run-BLACK.BOX-Universal.bat`: он создаёт виртуальное окружение, устанавливает открытые зависимости и запускает интерфейс. Либо:

```sh
python -m pip install -r requirements.txt
python -m pip install -e .
python app.py
```

Отдельно существует консольное ядро (обычному пользователю Windows оно **не нужно**):

```sh
python -m blackbox_rep_alva list
mkdir sessions
python -m blackbox_rep_alva record --pid 1234 --output sessions --duration 10 --interval 0.5
python -m blackbox_rep_alva summary "sessions/session-REPLACE_WITH_ID"
python -m blackbox_rep_alva compare "sessions/session-REPLACE_WITH_FIRST_ID" "sessions/session-REPLACE_WITH_SECOND_ID"
```

Для CLI замени PID `1234` на PID нужной программы, а названия папок — на значения, которые вывела команда `record`. Есть также команда `export` — полный список: `python -m blackbox_rep_alva --help`. Проверка тестов: `python -m unittest discover -s tests -v`.

## Конфиденциальность, ограничения и состояние проекта

- **Локальная работа:** для наблюдения не нужны облачная учётная запись, отправка логов, туннель, внедрение кода, изменение чужого процесса или фоновая служба. Опциональная проверка обновлений отправляет только запрос за открытыми данными релизов GitHub. Кнопки GitHub/почты открывают браузер или почтовую программу, но не отправляют отчёты.
- **Ограничение наблюдения:** доступные пользователю процессы и показатели ОС. BLACK.BOX **не читает автоматически** исходники, пароли, документы, стеки вызовов или внутренние исключения чужих приложений; сами графики **не доказывают** утечку памяти или причину сбоя.
- **Лицензия:** новый открытый код BLACK.BOX распространяется по [MIT](LICENSE). **Закрытая Alva не получает эту лицензию и не входит в дистрибутив.** У PySide6, psutil и других зависимостей собственные условия распространения, которые необходимо проверить перед окончательным выпуском.
- **Проверки:** кандидат v0.3.0 прошёл **49 тестов Windows и 49 тестов Linux**, а также автоматический запуск упакованного Windows GUI и служебного EXE — [GitHub Actions #39822604822](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/actions/runs/39822604822). **Настоящая приватная Alva, обновление/удаление на пользовательском Windows и широкая совместимость с чужими приложениями ещё не подтверждены.**
