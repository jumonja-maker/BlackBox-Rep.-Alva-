## Выберите вопрос для записи

| Задача | С чего начать | Что изучить и сохранить |
| --- | --- | --- |
| Воспроизвести замедление, рост памяти или всплеск I/O | Выбрать процесс, записать нагрузку и отметить нужный момент | Временную шкалу, счётчики, пропуски и находки со ссылками на источники; локальные SQLite/JSON/HTML |
| Сравнить два запуска одной нагрузки | Сохранить сопоставимые цель, профиль, интервал и условия работы | Сравнение сеансов/действий с числом повторов, разбросом и несовместимыми условиями |
| Изучить сохранённую трассу или сбой | Открыть ETL/EventPipe/JSONL в Trace Decoder либо соответствующий инструмент сохранённых источников | Отфильтрованные события, доступные стеки/символы и границы покрытия; экспорт JSON/HTML |
| Проверить диагностическую гипотезу другими данными | Открыть «Глубокое исследование» или Investigation Engine 3 внутри «Обзора» | Связи источников, частичный критический путь, гипотезы и отдельно подтверждённые шаги проверки |

CPU, RSS, I/O, ожидания и совпадения по времени — наблюдения. Сами по себе они не доказывают внутреннюю причину неисправности приложения. Неизвестные права, часы, символы и полнота данных остаются явными.

## Выбрать → записать → остановить → изучить

1. **Выбрать.** На странице **«Процессы»** найдите имя/PID, выберите нужный работающий экземпляр и подключитесь. Проверьте идентичность в **«Обзоре»**. PID вместе со временем создания отличает экземпляр; выбор файла или просмотр записанного потомка не начинает запись и не меняет живую цель.
2. **Записать.** До **«Начать наблюдение»** выберите **Standard**, **Detailed** или **Incident Burst** и проверьте интервал. Воспроизведите нагрузку. При необходимости отметьте проблему или границы действия; это заявления пользователя, а не подтверждённые сбои ОС.
3. **Остановить.** Нажмите **«Остановить наблюдение»** и проверьте статус сохранения/завершения. У записи SQLite и готовых отчётов отдельные состояния ошибки; ошибка отчёта не означает потери измерений. Сохраните показанный путь сеанса и повторяйте только неудавшуюся операцию.
4. **Изучить.** В «Обзоре» нажмите **«РЕЗУЛЬТАТ»** (подсказка **«Открыть результат записи»**) или **Ctrl+Shift+R**, когда остановленная запись готова. Это явно открывает её сохранённые данные в **«Отчётах»**; Stop оставляет текущую страницу. В «Отчётах» также открываются другие сохранённые сеансы. До чтения находок проверьте сеанс, экземпляр, интервал и покрытие, затем уточните диапазон, сравните или экспортируйте данные.

В «Отчётах» видны папка/диапазон открытого анализа и переходы **«Шкала»**, **«Находки»**, **«Библиотека»**, **«Действия / SDK»** и **«Снимок / сравнение»**. Копирование контекста анализа помещает его в локальный буфер обмена; проверьте его перед передачей. **Ctrl+1…6** переключает шесть страниц; **Ctrl+L** открывает «Процессы» и фокусирует поиск. **«Текущее наблюдение»** / JSON текущего наблюдения и **«HTML последней записи»** сохраняют указанный источник живого наблюдения/последней записи; они не экспортируют отдельно открытый сохранённый анализ. **«Последнее сравнение»** указывает две собственные папки и не меняет анализ или живую цель.

Для воспроизводимых экспериментов указывайте версию приложения, нагрузку и условия записи. Обычное наблюдение не запрашивает UAC. Профили не включают ETW, EventPipe и дампы автоматически.

## Наблюдение, исследование и вмешательство

| Область | Что означает |
| --- | --- |
| **OBSERVE** | Чтение доступных системных счётчиков выбранного процесса. Память цели не изменяется. |
| **INSPECT** | Отдельные запросы и снимки в «Глубоком исследовании». Доступ, поддержанные источники и чувствительные данные зависят от операции; снятие дампа может кратко приостановить цель. |
| **INTERVENE** | Явные отладочные действия, приостановка/возобновление потоков или изменение выбранных байтов памяти. Нужны подтверждение операции/цели и соответствующий доступ; наблюдение их не запускает. |

GUI не повышает собственные права. В исходниках R10 используется ограниченный по области и времени Diagnostic Helper; каждое вмешательство сохраняет отдельное согласие и проверку PID/времени создания. Включение прав не разрешает все последующие действия. Защита Windows может отказать в доступе. Неизвестное выполнение или очистка остаются неизвестными; откат после аварии не гарантируется. [Глубокое исследование](docs/BB_DEEP_001_RU.md) · [Границы R10](docs/R10_RU.md).

## Портативный комплект и локальные данные

Полностью распакуйте опубликованный ZIP в доступную для записи папку и запустите **`BLACK.BOX-Universal.exe`**. Сохраните `_internal` и все сопутствующие файлы. Портативной программе не нужны отдельный Python, учётная запись, подписка или обязательный облачный сервис.

| Исполняемый файл | Назначение |
| --- | --- |
| `BLACK.BOX-Universal.exe` | Основное приложение |
| `BLACK.BOX-Maintenance.exe` | Помощник обновления/удаления, обычно запускаемый приложением |
| `decoder/BLACK.BOX-Decoder.exe` | Автономный офлайн-декодер TraceEvent со своим runtime, запускаемый при необходимости |

Для EXE читаются метаданные и можно найти работающий экземпляр по полному пути. Запуск выбранного EXE требует отдельного подтверждения. Остальные файлы дают метаданные; выбор файла ничего не исполняет. SHA-256 вычисляется локально для файлов до 16 МиБ. Это не антивирусная проверка и не статический анализ кода.

Папка записи по умолчанию:

```text
%USERPROFILE%\Documents\BLACK.BOX Universal\sessions\
└── <session-folder>\
    ├── session.sqlite3  # Измерения и события жизненного цикла
    ├── report.json      # Структурированный итог
    └── report.html      # Офлайн-отчёт
```

У дополнительных захватов и анализов свои файлы и состояния. Экспорт для передачи создаёт отдельную копию с редактированием известных чувствительных полей; оригиналы остаются локально. Память/дампы и raw traces требуют отдельного включения. Редактирование известных полей не распознаёт любой секрет в свободном тексте: проверяйте экспорт перед передачей. Контрольная сумма подтверждает байты, а не доверенное авторство. Наблюдения не отправляются автоматически.

**«Проверить обновления»** использует опубликованные GitHub Releases, проверяет размер/SHA-256 ZIP и вызывает Maintenance после закрытия приложения. Проверка при старте включена по умолчанию и отключается в «Настройках». Сеансы в Documents должны сохраняться при обновлении/удалении. [Обновление, обратная связь и удаление](docs/UPDATES_FEEDBACK_UNINSTALL.md).

## Исходники и CLI

Используются Python 3.11+, PySide6/Qt, psutil, SQLite и `blackbox_core`. Для этого патча действует [AGENTS.md](AGENTS.md): запуск приложения/тестов/сборок разрешён только на GitHub-hosted runners; локально разрешены чтение и правки исходников. Обычная настольная поставка — портативный ZIP.

Необязательный CLI поддерживает `list`, `record`, `summary`, `compare` и `export`. Папка `record --output` должна существовать заранее:

```powershell
python -m blackbox_core list
python -m blackbox_core record --pid 1234 --output .\sessions --duration 10 --interval 1
python -m blackbox_core summary .\sessions\<папка-сеанса>
python -m blackbox_core compare .\sessions\<первый-сеанс> .\sessions\<второй-сеанс>
```
