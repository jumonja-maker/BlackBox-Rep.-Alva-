## Замена восьмичасового Standard по решению владельца

Владелец явно разрешил считать **5 ч 30 мин непрерывной записи Standard**
достаточным для практической приёмки именно этого длительного сценария,
учитывая шестичасовой предел GitHub-hosted job и отсутствие
отдельного физического стресс-стенда. Это **OWNER-ACCEPTED ALTERNATIVE**
для части endurance gate, но не утверждение, что реально проведено восемь
часов, и не ретроактивный PASS исходной нормы M-064 целиком.

Исходная M-064 содержит также час Detailed, 300 потоков, 100 потомков,
100001+ строк, 10000+ событий, 500+ инцидентов и ограниченный доступ к
произвольному интервалу. Эти части проверяются отдельными источниками;
для проверки M-064 в целом требуется полная матрица evidence. Физическая
Windows и замеры overhead не заменяются CI.

**Доказательства:** [Actions #40200792472](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/actions/runs/40200792472),
[полный CI #40200792479](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/actions/runs/40200792479),
source SHA `1266104f62f521984e0adc6b547eb811a9d38109`:
Standard 19800 с, Detailed 3600 с, real v1/v2 parity,
`CLOSED/COMPLETED`, выбранный export, PASS. Standard применял
адаптивное снижение частоты; это не доказательство постоянной частоты 2 с.

## Что потребуется для настоящего пользовательского обновления

Опубликованная стабильная версия сейчас — `v0.3.6`. Действующий
`check_latest_release()` объявляет обновление только для строго более
поздней семантической версии GitHub Release с официальным именем
`BLACK.BOX-Universal-Windows.zip`, подтверждёнными byte size,
GitHub release asset `sha256:` digest и допустимым URL. Не опубликованный
commit или артефакт Actions не будет предложен кнопкой «Обновить».

Следующий кандидат в PR — `0.4.0` (сам по себе **НЕ РЕЛИЗ**).
На Windows CI запускается `tools/qa_windows_maintenance_e2e.py`:

1. Берёт именно официальный `v0.3.6` ZIP с зафиксированными SHA256 и
   размером, распаковывает через защищённый production extractor.
2. Запускает настоящий old frozen GUI `--smoke`, сохраняет
   `logs/sessions/reports`, отдельные пользовательские данные и чужой
   файл рядом с установленной папкой.
3. Проверяет новый собранный release-candidate ZIP по SHA256 и
   `blackbox-build.json` (точный проверяемый SHA/tree), готовит
   обновление production `stage_release()` без обращения к вымышленному
   официальному `v0.4.0` на GitHub.
4. Запускает **старый** настоящий frozen `BLACK.BOX-Maintenance.exe`
   из внешней временной папки с `--update --wait-pid`;
   проверяет замену EXE, исчезновение старых application files и
   backup/staging, сохранность всех трёх data dirs, внешних файлов.
5. Проверяет реальный автоматический перезапуск **нового** GUI, новый
   frozen `--smoke` и созданный штатный Windows desktop shortcut.
6. Запускает **новый** настоящий frozen maintenance из вне папки с
   `uninstall --wait-pid` и проверяет: папка программы полностью
   исчезла, её ярлык отсутствует, внешний пользовательский файл и
   сохранённые диагностические данные остались нетронутыми.

Тест строго запрещает запуск вне временной директории disposable
GitHub-hosted Windows runner. Изменять настоящий компьютер владельца,
случайные системные пути, настройки Windows или другие установленные
приложения он не должен. QA ZIP отражает реальную упаковку того же
приложения, но **не** подтверждает будущую публичную GitHub загрузку
неопубликованного v0.4.0, физическую работу update dialog, real-world
ACL/AV/OneDrive или полную очистку недокументированных пользовательских
каталогов. Данные расследований по умолчанию сохраняются, не удаляются.

## Релизные блокировки, не снятые этим решением

- Нативный test old→new→uninstall должен PASS на exact candidate SHA
  прежде, чем можно заявлять обновление и удаление проверенными в CI.
- Не проведены физические Win10/11, полный update/uninstall с
  UAC, ACL, AV, OneDrive, screen reader/keyboard и installed-machine QA.
- 128 исходных нормативных пунктов не получили полного независимого
  signoff. Решение владельца по 8h снимает только один конкретный
  срок испытания и не превращает остальные невыполненные требования в PASS.
- Результат source/frozen GitHub QA не является гарантийным заявлением,
  что Windows удалит любой непринадлежащий приложению файл или любые
  диагностические сеансы вне portable installation.
- Workflow `shell-qa.yml` выпускает только ранее авторизованный
  `v0.3.6` из `main`; текущий новый `0.4.0` на Draft PR
  намеренно не приводит к автоматической публикации.

**Gate:** до разрешения оставшихся обязательных требований сохранять
PR #17 Draft, `main` по прежнему SHA, не публиковать GitHub
Release/tag и не заменять существующий официальный `v0.3.6`.


## 26.10.2026 — фактический native FAIL и инженерная коррекция

**Первый новый результат:** GitHub Actions
[40231766202](https://github.com/jumonja-maker/BlackBox-Rep.-Alva-/actions/runs/40231766202),
точный HEAD `5536e39c671569f05339e1187a0d5275c27a1bb3`:
Windows source и Linux source — SUCCESS, настоящий portable EXE startup/research —
SUCCESS, но native old-v0.3.6→new-v0.4.0→uninstall — **FAIL**. В
`tools/qa_windows_maintenance_e2e.py:297` обнаружен
`QaFailure: APP_SHORTCUT_REMAINED`, артефакт
`BLACKBOX-NATIVE-UPDATE-UNINSTALL-QA` сохранён. Испытание НЕ зачтено.

**Узкое исправление:** удаление принадлежащего приложению `.lnk`
выполняется до `rmtree(install)`, пока цель ссылки существует. Если
удаление файлов не получилось, оригинальные байты удалённого ярлыка
восстанавливаются эксклюзивно, не перезаписывая чужой ярлык. Отсутствие
ярлыка или его ссылка на другое EXE не являются разрешением трогать
произвольный путь. Добавлены регрессионные тесты.

**Сопутствующее требование владельца «удалить приложение полностью»:**
удалять только собственную ветку Qt QSettings в HKCU (не соседние
разделы) и transient frozen maintenance helper в контролируемой
отдельной `bb-maintenance-*` папке. Временный исполнитель запускает
ограниченную уборку после собственного выхода, не удаляя чужие
файлы из temp-папки. Тест теперь требует отсутствие этих остатков,
сохранение любых внешних файлов и диагностических сеансов/отчётов.

Версии `blackbox_universal.__version__` и `pyproject.toml`
выровнены на `0.4.0`; README направляют к фактическому
официальному latest Release, а не к несуществующему ZIP. Добавлен
ограниченный путь **ручной** публикации из `main` по точному
одобренному SHA с полным повторным Windows/Linux/frozen/native QA и
защитой уже существующего тега. Автоматический push main релиз не
выпускает.

**ВНИМАНИЕ:** перечисленные правки — инженерная попытка устранить
причину отказа, а не доказательство PASS. Новый exact-HEAD CI,
реальная проверка helper cleanup, отсутствие остатков, доступность
официального v0.4.0 через GitHub API и физическое пользовательское
обновление должны быть проверены отдельно. Draft PR #17 сохраняется;
документ не даёт разрешения скрывать физические/128-point ограничения.
