Каноническая версия исходников — **0.6.0, неопубликованный кандидат**. Подтверждённый опубликованный комплект — **v0.5.4**.

## Область и способ проверки

Исходная задача — полноценный рабочий путь опытного пользователя: выбор процесса → запись → Stop → явное открытие результата → анализ сохранённого источника. В том же PR пользователь расширил задачу до технической инспекции программы, включая Chain Builder, Deep Inspection и Investigation Engine 2/3. Сохранены шесть production-страниц и прежний пятистраничный embedding API. Новые коллекторы, новые виды native-действий или обход подтверждений не добавлены.

Область вышла за интерфейс: изменены admission/finalization записи, проверка birth в sampler, владение guardian/native-ресурсами, точечный native cleanup, shared diagnostic queue, persisted Chain scheduler/head binding, читатели, экспорт и QA. Поэтому формулировки «только UI», «базовый sampler без изменений» или «все helper/scheduler-пути без изменений» к общему патчу неприменимы. Ни один короткий GUI-прогон не заменяет обязательные длительные проверки этих изменений.

Локально разрешены и выполнены чтение исходников, правки, Git/source review и создание документов. **Приложение, тесты, compiler, build, native и endurance локально не запускались.** Выполнение остаётся исключительно GitHub-hosted.

Обновлённая документальная инвентаризация содержит 258 source/tooling-файлов и 3461 лексическое определение, включая классы и вложенные helpers; первоначальный снимок содержал 254/3352. Финальные строки после всех правок сверяются при freeze. Это список кандидатов, не измеренное function/branch coverage. Детальные owner-checklists различают прочитанные тела/границы, делегированное и непроверенное. Например, analysis/integration прочитаны по 30 модулям/471 лексическому определению; у QA/tooling остаются явно отмеченные непроверенные внутренние функции. Новые определения после снимка требуют обновления итоговой инвентаризации. Заявления «каждая функция выполнена» и «в программе больше нет ошибок» не делаются.

## Сохраняющиеся ограничения

- Не все UI reads асинхронны: legacy session bounds, file/EXE inspection, часть index/PDB/clock/export могут ждать slow I/O. Полный Raw JSON/tree/export всё ещё может быть большим; нет универсальной latency/RAM гарантии.
- Noncooperative native call и ambiguous close сохраняют owner/recovery-unconfirmed. Cancel/request/helper exit не доказывают, что действие не выполнялось или kernel resource освобождён.
- Общая схема/history/hash/source stamp дают integrity и выбранный scope, а не authenticated provenance, live authority, точную FILETIME из float или восстановление отсутствующих событий/часов.
- Physical Windows10/11, UAC Secure Desktop, AV/locks/OneDrive, physical DPI, screen reader/ассистивные средства и все ABI/provider версии не подтверждены source review/offscreen Qt. Возможности/PPL определяет Windows; explicit skip остаётся непроверенным.
- EXE unsigned. SHA подтверждает байты, не безопасность/Authenticode reputation; notices не заменяют полный license/legal/dependency audit.
- Memory/dumps/ETL/пути/free text могут содержать секреты. Share export редактирует известные поля, но не распознаёт любой секрет; clipboard/export остаются явным решением пользователя.
- CPU/RSS/I/O, совпадение по времени, BLOCKED, WCT, successful diagnostic action не доказывают root cause/lock owner/leak/speedup. GC elapsed не равен stop-the-world pause, CPU samples не равны CPU time/percent, disk request timing не равен application API latency.
