# BLACK.BOX Universal — технический forensic-аудит исходников (27.10.2026)

**База:** `main` = `cf2fe466e4956bde30b4fcfe61fd365d3b26ff75` до патча.
**Объект:** Windows PySide6 + изолированный процесс наблюдателя; SQLite schema1/schema2,
интервальные и пользовательские измерения, дерево процессов и потоков, ETW/EventPipe/GC,
журнал событий, экспорт, переносимая сборка, обновление, хранение и удаление.
**Задача:** исключить правдоподобные, но ложные результаты, скрытые потери и нарушение
выбранной пользователем приватности. Проверено чтением фактических функций и
изолированными воспроизводимыми примерами, не только наличием зеленого CI.

ВНИМАНИЕ: это *проверка исходного кода и синтетические регрессионные сценарии*,
а НЕ аттестация реальной точности Windows 10/11 в конкретном окружении.
Новый Release / тег не создаются по прямому запрету владельца.

## Доказанные ошибки, исправляемые одним патчем main

|---|---|---|---|

**Регрессии:** `tests/test_forensic_audit_20261027.py` включает 9 случаев:

несогласованные флаги качества, CPU через смену каденции, искаженную

## Проверенные существующие защитные границы

- **Psutil:** привязка PID + creation_time при attach/start/sample, свежая
  перепроверка PID, NULL для недоступных I/O и процессов, CPU как доля ОДНОГО
  логического ядра. Между сэмплами неизвестное поведение не превращается
  в «0 нагрузки».
- **Каденция:** `MonotonicSampleCadence`, основной `SessionView.interval`
  и метрики эксперимента уже прерывают CPU/I/O интегрирование при смене
  периода, неизвестной паузе и сбросе счетчика. Ошибка AUD-02 была отдельным
  упущенным SQL-потребителем.
- **Хранилище:** schema1 и schema2 записываются отдельно. При финализации
  `confirm_v2_completion` требует CLOSED, совпадение UUID/origin/exit_code,
  непрерывную последовательность и отображение `schema1:seq`. При реальном
  провале schema2 нельзя маркировать primary как успешный финал.
- **Исследование:** `user_problem` — команда человека, не факт сбоя ОС;
  `AUTO_INCIDENT_COMPLETED` — наблюдаемый порог, а не доказанная причина.
  Окна WCT и WM_NULL могут быть недоступны/усечены по разрешениям и лимитам.
- **ETW/EventPipe:** Windows WPR и dotnet-trace работают по явной команде.
  TraceEvent 4.0.0 декодирует импортированную трассу в дочернем процессе,
  оригинал хешируется; нет автоматической загрузки символов. `GC_ELAPSED_NOT_PAUSE`
  не должен называться длительностью stop-the-world паузы.
- **Экспорт и удаление:** используются отдельные каталоги подготовки,
  исходные сессии не мигрируются на месте, удаление пользовательской библиотеки
  требует подтверждения и проверки принадлежности.
- **CI:** до патча коммит `cf2fe466` прошел Windows source, Linux и Windows
  portable. Тем не менее все восемь сценариев возможны, несмотря на зеленый CI:
  они не моделировались существующими тестами.

## Оставшиеся принципиальные границы (не считать устраненными)

1. **Пробелы наблюдения:** невозможно доказать отсутствие необнаруженных
   переключений потоков, коротких процессов, пропущенных OS/ETW событий
   или всех UI-зависаний только по `psutil` и WM_NULL. Число потерянных
   событий может быть `None`, а не 0.
2. **Нагрузка наблюдателя:** `ObserverBudget` измеряет только выбранные
   компоненты, не полный процессный лес и не реальный эксперимент OFF/ON.
   Порог CPU — рекомендация, НЕ доказанный накладной расход наблюдателя.
3. **GC и символы:** отсутствие rundown/манифеста/PDB не может быть восполнено
   декодером. Отсутствующие стеки и неизвестные payload полей остаются
   UNKNOWN; одиночные GC Start/Stop не являются измерением паузы UI.
4. **Ограничения Windows:** не проверялись физические Win10/11, OneDrive,
   блокировки AV, UAC/ACL, недоверенные файлы со сложными reparse point,
   реальные окна с WCT и screen reader; GitHub Windows runner недостаточен.
5. **Масштабирование:** процессный список после исправления содержит все
   обнаруженные имена/PID, но полная IPC-передача огромного каталога и
   QTableWidget при сотнях тысяч процессов остается потенциально дорогой.
   Следующий этап — серверная пагинация/фильтр с snapshot/identity.
6. **Приватность и политика раскрытия:** «без идентификаторов» не означает
   математическую анонимизацию. UTC время, форма CPU/RAM, имена известных
   провайдеров и некоторые тексты событий сами по себе могут коррелировать
   с конкретным пользователем или приложением. Для отправки третьим лицам
   нужен отдельный redaction/consent review.
7. **Надежность демона и файлов:** Unix/Windows Job владеет дочерним декодером,
   но изоляция процесса не является OS security sandbox. Против недоверенных
   бинарных трасс нужно дополнительно испытать ограничения RAM/диска,
   поврежденные ETLX/SQLite и внезапное завершение.
8. **Runtime у разных приложений:** настоящий .NET EventPipe подтвержден
   тестовым EventSource с GC/стеками, но не всеми версиями .NET, WPP/TMF,
   Minidump/ClrMD и произвольными proprietary форматами.

## Рекомендуемая приемка именно этого патча

1. Выполнить новые регрессии отдельно, затем весь unittest на Windows/Linux.
2. Frozen portable EXE: --smoke, research-e2e, deep-smoke, стандартный токен,
   SHA/подписи артефактов. Не принимать Windows ZIP до успеха platform job.
3. Сравнить оригинальную SQLite до/после read-only анализа по SHA-256.
4. На реальной Windows 10/11: выбрать процесс с индексом >500 через PID,
   записать Standard/Detailed с изменением cadence, импортировать испорченную
   sqlite-копию, проверить статус отказа без «0% CPU», экспортировать интервал
   без PID/TID/creation_time и проверить ZIP/JSON/HTML/CSV на утечки.
5. Долгий тест и OFF/ON измерение отдельной процедурой, не подменять CI.
