# Internal diagnostic engine — no branded screen (owner decision, 2026-10-22)

## Product contract

**BLACK.BOX Universal is the visible product. Alva is developer infrastructure, not a separate page, lab, upsell, integration wizard or end-user task.** The main window, side navigation, View menu, About dialog and first-run journey must never expose a branded Alva tab. The application has exactly five pages: Overview, Processes, Event Log, Reports, Settings.

Ordinary user journey is **select process → start → stop → read report**. Local sampling and reports are always part of BLACK.BOX, whether a platform runtime is installed or not.

## What is actually available at this SHA

- BLACK.BOX process sampling (psutil), SQLite, report.json and report.html are implemented by its own public code. **They are not the Alva Python package.**
- An optional, previously authorized interpreter path (existing QSettings `BlackBox / BLACK.BOX Universal / alva_python`) can activate the *already existing* external Alva sidecar **automatically after Stop**. A private runtime is not imported while sampling or during normal UI launch. Its work uses three predefined scoped operations about saved observer summaries and may append `alva-diagnostics.json`.
- If no authorized interpreter was already configured, the app **does not** launch Python, fetch packages, change registry keys, ask for login, send data to a cloud service, or claim real Alva execution. It still produces the standard reports. A prior user preference is a local deployment configuration, not a guarantee of Git provenance.
- The private platform repository remains private; its source code, wheels and runtime are neither imported into public source nor bundled into downloadable public PyInstaller binaries.
- The user interface has **no** Alva toggle or separate environment chooser. Maintainers can provision/revoke the legacy allowed interpreter preference in a trusted environment outside the public UI; do not silently set it based on arbitrary PATH or common Python installs.

## Maintainer configuration only

In an explicitly authorized, locally trusted Python/PySide6 environment, the setting can be prepared or removed before application launch using the same Qt organization and application names:

```python
from PySide6.QtCore import QSettings
settings = QSettings("BlackBox", "BLACK.BOX Universal")
# Provision only an approved, separately installed interpreter with Alva:
settings.setValue("alva_python", r"C:\trusted-venv\Scripts\python.exe")
# Revoke optional private runtime:
settings.remove("alva_python")
```

**Do not ship a default private path or deploy these commands to unconsenting computers.** A user-selected Python executable runs code with the user's own permissions; `-I` is not a security sandbox. The current sidecar uses bounded JSON and explicit operation names but does not authenticate a wheel or Git SHA. The three operations cannot prove root cause inside another application.

## Future default true Alva for every user

A true no-setup experience with real Alva on every public Windows machine requires **an owner-authorized redistribution/licensing decision and a vetted Alva runtime package** OR an approved external hosted service. Both are **NOT IMPLEMENTED**, and the existing offline/no-server design does not allow a hidden remote solution. Until one is approved, never advertise the native BLACK.BOX diagnostics as if they were generated by Alva.

Once runtime distribution is permitted, a tested internal runtime provider can be added without restoring any Alva-branded UI. It must pin SHA/digest, verify trusted signatures and library identity, provide opt-out/rollback, and pass real Windows and Ubuntu consumer tests.

## Test and release gates

- Exactly five pages, zero Alva-branded labels/buttons/platform menu pages, in both EN and RU.
- CLI/API and private sidecar remain behind the same source boundaries; no target-process mutation and no internet for observation.
- No configured runtime ⇒ no sidecar execution; all usual reports still save.
- Previously approved runtime + finalized report ⇒ at most one background sidecar attempt per session; on failure preserve original report and preserve provenance markers.
- Real frozen Windows EXE smoke on exact PR SHA and normal user experience before promotion. Private genuine Alva acceptance remains **NOT RUN**.
