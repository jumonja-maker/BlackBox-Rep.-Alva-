# BLACK.BOX TRACE DECODER — Phase 2: честный анализ GC и выборок CPU

**Исторический контракт Phase 2.** Следующий Phase 3 дополняет индекс
наблюдаемыми календарными метками UTC без доказанной синхронизации
с сеансом: [Phase 3](TRACE_DECODER_PHASE3.md).

**Только разработка в main.** Не является официальным релизом и не изменяет
сбор данных в процессе наблюдения. Microsoft TraceEvent остаётся оригинальной
NuGet-зависимостью 4.0.0; BLACK.BOX расширяет *offline* SQLite-адаптер.
Никакие PDB/символы из сети не загружаются, записи ETW/EventPipe не запускаются.

## Почему разделили стеки

В действительном EventPipe QA-артефакте предыдущей сборки из 56 645 событий
36 196 имели прикреплённые стеки. Однако только 499 событий в этой
конкретной трассе были подтверждёнными
\`Microsoft-DotNETCore-SampleProfiler / Thread/Sample\`.
Большинство остальных стеков относились к GC/AllocationTick и другим
событиям runtime. Называть все 36 196 стеков «выборками CPU» было бы
методологической ошибкой.

Новая вкладка показывает отдельные представления:

1. **Event-associated stacks / Стеки событий** — исходные кадры без
   интерпретации как CPU-время (старое представление не менялось).
2. **CPU profiler samples / Выборки CPU-профилировщика** — только точное
   совпадение поставщика и типа Thread/Sample. Стеки группируются по
   записанным адресам, именам и признаку усечения, по PID и идентификатору
   экземпляра процесса в трассе. Количество показов — число **записанных
   событий выборки**, а НЕ доля CPU, секунды процессора или время выполнения.
   Сортировка по количеству записанных выборок и постраничное чтение.
   Фреймы с отсутствующими символами остаются пустыми; адрес сохраняется.
   Неизвестный экземпляр процесса нельзя объединять с другими строками
   только по PID, поскольку возможен reuse.
3. **GC statistics by generation / Статистика GC по поколениям** —
   группировка действительных пар GCStart/GCStop по PID, экземпляру
   процесса, CLR-instance, поколению, GC-типу. Отдельно показаны
   \`RUNTIME_SUSPENSION_ENVELOPE\` и \`RUNTIME_FULLY_SUSPENDED\`.
   Статистика содержит число пар, сумму их длительностей, минимум и
   максимум, ссылки на исходные события. **Сумма не равна суммарной паузе
   приложения или wall-clock времени** и может включать перекрытия.
   \`GC_ELAPSED_NOT_PAUSE\` — не stop-the-world и не причина задержки UI.

Во всех режимах сохраняются PID-фильтр, буквальный поиск, keyset-пагинация и
подробный JSON просмотра. Импортированная трасса остаётся UNVERIFIED_IMPORT,
а время до сеанса BLACK.BOX не калибруется.

## Индекс, пределы и качество

\`blackbox.decoder-index/2\`, SQLite PRAGMA user_version=2. Новые таблицы
\`stack_profiles\` и \`gc_profiles\` создаются *после* записи исходных событий;
публикация проходит только после подтверждённого завершающего footer.
Никакое старое сохранённое доказательство не переписывается.
Сохранённые индексы v1 можно читать в прежних режимах Events/Stacks/GC;
для новых сводок необходимо заново декодировать **оригинальную трассу**.

Сохраняются ограничения текущего декодера: до 250 000 исходных событий,
до 256 MiB входного файла и 128 кадров одного стека. Дополнительно
максимум 8 192 уникальные группы CPU-стеков. При превышении бюджета
\`cpu_profiler_samples_omitted_from_groups\` увеличивается: приложение
не говорит, будто группировка полная. Учитываются выборки без стеков,
выборки без известного экземпляра процесса и общий объём профиля.
SHA-256 исходной трассы проверяется до и после импорта.
Это не ОС-песочница: недоверенные бинарные ETL/NETTRACE всё ещё зависят
от корректности Microsoft TraceEvent и CLR runtime.

## Проверки

Синтетические тесты (это **не** доказательство нативного ETW/GC):
- разные экземпляры процесса не смешиваются при совпадении PID и кадров;
- отсутствие process instance предотвращает недоказанную агрегацию;
- GC Gen2/CLR-instance и интервалы остановки не приписываются к UI;
- \`%\` и \`_\` остаются буквальными при поиске;
- лимит групп и количество неагрегированных выборок согласованы;
- старый v1 индекс остаётся читаемым в прежних режимах;
- режимы новой вкладки и единицы SAMPLES/PAIRS проходят RU/EN Qt QA.

Настоящий нативный тест \`tools/qa_decoder.py\` изолированно записывает
\`.nettrace\` EventSource с GC и SampleProfiler и проверяет число
\`Thread/Sample\` в исходных SQLite-строках против сумм новых групп.
Он также проверяет соответствие числа GC пар статистике.
На disposable Windows CI проверяется реальный ETL. Эти тесты не являются
полной приёмкой Win10/11, WPP/TMF, ClrMD, собственных PDB или продольной
нагрузки целевого приложения.
