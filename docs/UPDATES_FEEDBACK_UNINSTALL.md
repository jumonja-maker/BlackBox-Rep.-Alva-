# Обратная связь, RU/ENG, обновления и удаление — BLACK.BOX Universal

## Где расположены элементы

- Внизу левой панели (пустое место на скриншоте) размещены компактные
  кнопки **GITHUB**, **E-MAIL**, **RU** и **ENG**, оформленные маленькими
  объёмными ретро-элементами. Переключение языка происходит без
  перезапуска и сохраняется в локальных настройках QSettings.
- В свободной области верхней панели расположена **ОБНОВИТЬ / CHECK
  UPDATES**. После подтверждённой более новой версии кнопка становится
  светло-зелёной. Никаких зелёных обещаний при сетевой ошибке, отсутствии
  релиза или неподтверждённом SHA-256.
- В **Settings** добавлены «Создать ярлык» и «Удалить программу».
  Ярлык — настоящий Windows `.lnk`, использует оригинальную иконку
  стилизованного пиксельного монитора с диагностическим сигналом.
- Страница Overview теперь сбрасывает прокрутку в начало при открытии,
  чтобы заголовок и карточки ресурсов не исчезали над верхней панелью.

## Локализация

RU/ENG меняет навигацию, заголовки экранов, подписи виджетов,
подсказки, справку, статусы и команды. Имена наблюдаемых процессов,
сырые события, числовые метрики и ключи JSON не переводятся:
это технические данные, которые должны быть неизменными.

## Проверка обновлений

На старте выполняется **единственный запрос** метаданных к
`https://api.github.com/repos/jumonja-maker/BlackBox-Rep.-Alva-/releases/latest`,
если в Settings включён флаг автоматической проверки (по умолчанию
включён). Передаются стандартные HTTP-метаданные соединения; **логи,
PID, отчёты и документы никогда не отправляются**.
Автоматическую проверку можно отключить. Кнопка позволяет проверить
наличие версии вручную.

Новый релиз считается доступным, только если:

1. Он не `draft` и не `prerelease`; тег — строго `vX.Y.Z`.
2. Версия больше встроенной в EXE.
3. В релизе есть архив `BLACK.BOX-Universal-Windows.zip` с
   правильной официальной ссылкой GitHub.
4. API GitHub возвращает SHA-256 этого архива (`digest: sha256:...`).

Скачивание **не выполняется автоматически**. После подтверждения
пользователем ZIP загружается рядом с установленной папкой, сверяется
длина и SHA-256, ограничиваются количество файлов, суммарный размер и
пути внутри архива; запрещены выход за каталог и символьные ссылки.

Затем отдельный `BLACK.BOX-Maintenance.exe` ждёт завершения главного
процесса, меняет каталоги, переносит старые `logs/`, `sessions/`,
`reports/` и удаляет прежнюю версию. При сбое до удаления резервной
копии выполняется откат. По успешному завершению остаётся **ровно
одна актуальная версия** без каталога предыдущего приложения.

**Примечание:** GitHub Actions artifacts из PR — это не Releases.
Зелёная кнопка появляется лишь после создания официального релиза
с новым семантическим тегом. Тег можно публиковать после слияния в
main и выполнения полного Windows/Linux QA. Бинарник в PR сам по
себе не является обновлением для установленных пользователей.

## Полное удаление

Из Settings пользователь подтверждает удаление. Только собранная
**портативная** версия, имеющая собственный проверенный marker
`.blackbox-portable.json`, может вызвать удаление. Исходный код
и случайно выбранный каталог не удаляются.

Служебный EXE запускается отдельно вне папки приложения, ждёт
закрытия главного EXE и удаляет всю портативную папку,
включая старые runtime-файлы и служебные бинарники.
`logs/`, `sessions/`, `reports/` внутри папки приложения
предварительно переносятся в
`~/Documents/BLACK.BOX Universal/Preserved-<date>/`.
Данные сеансов, которые уже хранит программа в
`~/Documents/BLACK.BOX Universal/sessions/`, **не удаляются**.
Ярлык с рабочего стола удаляется только если его TargetPath
указывает именно на этот BLACK.BOX.

Права администратора для обычной портативной папки не запрашиваются.
Системные директории, symlink и неподписанные marker-каталоги
не используются как цели удаления. Удаление подтверждается пользователем;
никаких скрытых удалений при обновлении или закрытии программы нет.

При сбоях служебный EXE записывает код ошибки в независимый журнал
`~/Documents/BLACK.BOX Universal/maintenance-errors.log`.
Временная служебная копия EXE может остаться в системном временном
каталоге до его штатной очистки — она не является второй установкой
BLACK.BOX, не работает постоянно и не хранит отчётов.

## Дизайн и значок

Скрипт `tools/generate_icon.py` создаёт ICO в разрешениях 16–256px
и PNG из оригинальной пиксельной графики: бирюзовый компьютер,
коралловый акцент и мятная кардиограмма. Windows EXE получает
ICO как собственную иконку через PyInstaller, а пользовательский
ярлык автоматически использует иконку EXE. Сторонние изображения
или шрифты не распространяются.

## Матрица тестов

`tests/test_portable_maintenance.py` проверяет строгое сравнение
версий, метаданные релиза, отказ при неподтверждённом digest,
ошибке SHA-256, злонамеренном пути внутри ZIP, точную замену
версии, отсутствие резервных копий после успеха,
сохранение логов при uninstall, отказ удалять случайную папку,
переключение RU/ENG, работу ссылок и зелёное состояние только
для верифицированного объекта `Release`.

GitHub Actions дополнительно компилирует оба Windows EXE,
упаковывает значок и marker, выполняет `--smoke` оконного
BLACK.BOX и `--help` служебного EXE. **Ручная проверка полного
обновления и удаления на реальном Windows-компьютере обязательна
перед публичным стабильным релизом.**
