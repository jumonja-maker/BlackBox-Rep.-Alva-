# BLACK.BOX: исследование программы

Обычный режим работает с правами пользователя. Дополнительные права расширяют доступ к отдельным источникам, но не делают любой процесс полностью наблюдаемым. BLACK.BOX не внедряет DLL, не изменяет память цели и не обещает установить внутреннюю причину по внешним счётчикам.

## Начать

На «Процессах» выберите работающий PID либо файл программы и подтвердите найденный процесс. Выбор сам по себе не начинает запись. На «Обзоре» проверьте PID/идентичность и профиль, нажмите «Начать». Stop доступен только после успешного запуска. Одна цель — один экземпляр PID + время создания; просмотр потомка в истории не меняет цель.

Standard записывает базовые счётчики. Detailed добавляет потоки, потомков и memory queries. Incident Burst включает подробный опрос на ограниченное время после разрешённого триггера. Профили не включают ETW/дампы. Большое количество потоков/потомков имеет явный предел и число пропущенных элементов.

В «Настройках» можно выбрать интервалы, лимиты/триггеры и мягкие бюджеты. Высокая длительная нагрузка самого наблюдателя даёт предупреждение; по умолчанию опрос может замедлиться до 5 секунд. Это записывается как изменение условий. Автоснижение можно выключить до записи. Показатель собственной загрузки не доказывает её прирост по сравнению с выключенным наблюдением — для этого нужен benchmark.

## Действия и пометки

«Подготовить действие» → «Начать действие» → выполните нужное действие в своей программе → «Завершить». Повторы объединяются в эксперимент; незавершённый замер при Stop становится ABORTED. Время кнопок измеряет пользовательские границы, а не внутреннюю функцию приложения.

«Отметить проблему», начало/конец этапа и комментарий — заявления USER. Их время нажатия хранится отдельно от получения команды. Пометка не превращается в подтверждённый сбой Windows. Для точных внутренних границ можно добровольно добавить сгенерированный клиент приложения.

## Исследовать

На «Отчётах» выберите сохранённый сеанс/диапазон. В начале идут наблюдения, измерения и ограничения. Находки доступны страницами/сортировкой/вопросами CPU, UI, Memory, I/O, Coverage. Карточка инцидента содержит реальные снимки до/внутри/после, ресурсы/TID/дерево, доступные Win32/WCT/trace сведения и следующие измерения. Неполный post-context помечается явно. JSON открывается отдельно.

График использует общий временной диапазон, зум/панорамирование и курсоры A/B. Пропуски не соединяются нулём. Дорожки событий агрегируют выбранный диапазон; щелчок по событию переводит к соответствующему интервалу. «События» фильтруются по источнику, severity, экземпляру, времени и тексту. Данные из открытого файла не считаются аутентифицированными OS-фактами.

Сравнение показывает время, CPU, память/USS/private, handles, I/O bytes/ops, gaps/ошибки и доступные UI timeouts. Ноль отличается от «не наблюдалось». Видны число повторов, вариативность и отличия условий. Корреляция/дельта не доказывает ускорение или причину утечки.

## Подготовить свою программу

В раскрываемых инструментах исследования нажмите «Подготовить мою программу». Мастер создаёт локальные примеры Python/.NET/C++/Node и конфигурацию канала. Добавьте пример в исходники своей программы, соберите/перезапустите и дождитесь настоящего control event. Если код не меняется, доступно только внешнее наблюдение; BLACK.BOX не будет выдумывать внутренние этапы.

Python SDK: `stage` связывает этапы, `io_operation` измеряет wall latency добровольно обёрнутой операции. Это APP statement с отдельными часами, не физическое service time диска. Подробнее — SDK_GUIDE.md. Native PDB должен соответствовать EXE; неверные символы не принимаются как имена стеков.

## Дополнительные источники

Снимок Windows/WCT, короткая WPR ETW, EventPipe и минидамп запускаются отдельно. Для WPR есть Stop, TTL и журнал собственной случайной сессии. ETL может содержать сведения о других процессах. Если источника/прав нет, остаётся понятный статус; базовые счётчики работают дальше.

EventPipe использует только установленный dotnet-trace, без автозагрузки. Требуется подходящий .NET процесс и доступ к diagnostics port. Python/native/JVM не становятся .NET-процессами. Сохранённый nettrace может оставаться UNDECODED. Минидамп требует отдельного согласия: он содержит память и может кратко приостановить цель.

«Системные события сбоев» читает доступные записи Application EventLog. Совпадение именованного PID и UTC-окна не гарантирует внутреннюю причину и не исключает PID reuse. Отсутствие записей не доказывает отсутствия crash. «Прочитать сохранённый ETL» извлекает только поддержанные event headers, не дорисовывает stacks/GC/latency из заголовка.

## Сохранить и восстановить

Библиотека использует локальный индекс. Поиск не сканирует диск; поиск старых папок — отдельная команда. Можно открыть/сравнить/экспортировать запись, добавить локальный комментарий. Комментарий хранится в индексе, не меняет исходный сеанс и не входит в share export.

Экспорт по умолчанию создаёт отдельную копию с удалением известных чувствительных полей. Raw traces/dumps включаются только отдельным флажком и требуют проверки содержимого перед передачей. Автоматической отправки нет. JSON/CSV/HTML/ZIP содержат реальные доступные данные и ограничения; checksums проверяют целостность, не подлинность автора.

Корзина обратима и не освобождает место. Окончательное удаление требует отдельного просмотра/подтверждения только собственных записей. Активные/внешние/изменённые папки не удаляются как свои. Удаление не касается соседних проектов.

После прерывания экспорта в «Настройках» явно выберите выходную папку и проверьте журнал. Подготовленную выдачу можно завершить, незавершённую — очистить после отдельного согласия. Неизвестные новые файлы сохраняются. После аварии трассировки библиотека предлагает проверку собственных журналов: живой или чужой владелец блокирует очистку. Целевая программа не завершается.
