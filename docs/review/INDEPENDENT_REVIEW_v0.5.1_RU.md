## Что дополнительно воспроизведено и исправлено

1. Путь с пробелами **внутри сообщения** сохранял приватный остаток. Проверено
   не только регулярное выражение, но и настоящий share ZIP из синтетических
   SQLite-свидетельств: остаток попадал в evidence.csv. Теперь распознаваемый
   путь/URL скрывает всё строковое значение. Это сознательно консервативная
   потеря части диагностического текста в копии, не изменение оригинала.
2. `NOT LIKE 'sqlite_%'` принимал `_` за wildcard и пропускал пользовательскую
   таблицу `sqliteXextra`. Теперь сравнивается буквальный reserved prefix.
   Пользовательский trigger с похожим именем также не обходит запрет схем.
3. URI-pattern не начинает длинный поиск схемы с каждой буквы одного слова.
   Добавлен контроль длинной строки без пути. Это не полноценный fuzzing.
4. Screenshot workflow переведён в manual/artifact-only, без contents:write и
   без команды записи в main. Источник задаётся пользователем и проверяется по
   успешному run и SHA; фиксированный старый artifact больше не используется.
5. Подготовлена версия 0.5.1, включая embedded version в build provenance,
   проверку версии ZIP и реальное обновление с pinned официального v0.5.0.
6. Публикация черновика использует numeric release ID. До публикации сверяются
   main SHA, наличие чужого тега/релиза, ровно два assets и их серверные digest.
   Публичная старая версия, неоднозначные draft и несовпадение SHA блокируют выпуск.

## Проверки до отправки кандидата

Новые privacy-воспроизводители на исходной базе дали FAIL. После исправлений
прошли 46 выбранных тестов: privacy/reference/schema/ZIP, полный и частичный
экспорт находок/заметок, no-clobber, inventory и offline release/draft contracts.
Исходные SQLite-хеши проверены до и после default и sensitive экспорта.
Python compilation и YAML parsing прошли. Политика не является универсальной
анонимизацией; arbitrary attributes не раскрываются через согласие на notes.

Синтетический export-тест подменяет только наблюдение create_time владельца
транзакции, поскольку локальный procfs не является подтверждённой native средой.
SQLite, redactor, reports и ZIP не подменены. Это **не** Windows/Qt/EXE приёмка.
Полные Windows/Linux, Qt popup, реальные захваты/декодер и portable/update проверки
должны пройти заново на точном итоговом коммите до merge/publication.

Старые audit evidence сохранены как исторические, не выданы за результаты новой
версии. Первый абзац обоих README и Outlook сохранены. Ограничения декодера,
неподписанного EXE, физической Windows/AV/OneDrive/accessibility и endurance
остаются в release notes.
