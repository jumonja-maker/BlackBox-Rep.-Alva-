# BB-01 — необязательный индекс и завершение пользовательских стадий

База: 765156068a2d2f0171be4d048e74c7676feba143.

## Подтверждённая причина

`research_worker.py` использует `sqlite3.Error` в двух `except` (`_health`, `stop`), не импортируя `sqlite3`. SQLite-ошибка необязательного LibraryCatalog/storage_budget подменяется `NameError`, попадает в внешний recorder-loop и останавливает основную запись с STORAGE_ERROR. Такое же имя ломает обработчик ошибки закрытия активной пользовательской стадии.

Минимальное исправление — импорт стандартного `sqlite3`. Существующий бюджет индекса (чтение timeout .1s и cache 60s) и политика честного `INDEX_UNAVAILABLE` уже были реализованы; их не нужно переписывать. Ошибка завершения стадии теперь достигает существующего обработчика `USER_STAGES_FINALIZATION_UNCONFIRMED`, закрывает принадлежащие записи и оставляет research INCOMPLETE, сохраняя измерения. Основные наблюдения и состояние research различаются; INCOMPLETE не выдаётся за потерю всех записанных данных.

## Новые регрессии

`tests/test_audit_capture_20261028.py` содержит 6 проверок:

1. Настоящий изолированный helper через JSON-lines; повреждённый индекс, минимум 3 измерения, активная стадия, Stop; readback обоих SQLite и `user.stage_aborted`.
2. Реальная `BEGIN EXCLUSIVE` блокировка индекса; ограниченное ожидание, продолжение sampling; после снятия блокировки обновление budget.
3. Инъекция SQLite-ошибки закрытия пользовательской стадии; основная запись закрывается, измерения сохраняются, research INCOMPLETE.
4. Ошибка индекса кешируется и не вызывает запрос на каждый sample.
5. Переносимый контракт `_health` с явной не-нативной probe-границей: DatabaseError превращается в INDEX_UNAVAILABLE, recording остаётся активным.
6. Переносимый контракт `stop`: sqlite stage failure не мешает закрыть owner/store, sync legacy и research INCOMPLETE.

Первый красный прогон: 3 ERROR (NameError) + 1 FAIL (helper уже прекращён до stage begin). Лог `capture-red.log`. Это подтверждает ошибочный обработчик, но начальный локальный green из 4 тестов **не используется как доказательство правильной нативной записи** по причине среды ниже.

## Ограничение локальной среды и настоящий итог

В этом host `os.getpid()` и `/proc/self` относятся к разным PID namespaces. Число Popen.pid может совпасть с посторонним /proc PID, даже когда дочерний процесс уже завершён. В отдельном существующем exit-clock тесте это проявилось как PROCESS_NOT_FOUND либо отсутствие PROCESS_EXIT_OBSERVED. Не вносился обход в продукт и не заменялись реальные наблюдения поддельными.

Четыре новых проверки, которым нужен собственный реальный PID, имеют явный fixture guard: на таком host SKIP `CONTROLLED_PROCESS_NAMESPACE_UNAVAILABLE`. На обычном Linux с согласованным procfs и на Windows они исполняются; регрессии для Windows должны войти в окончательный CI. Две переносимые проверки не прикрепляются ни к какому процессу и проходят здесь с явно управляемой probe-границей.

Финальный локальный итог новых тестов: **2 PASS, 4 SKIP, 0 FAIL/ERROR** (`capture-final.log`). Прежний дополнительный набор дал 71 PASS / 2 SKIP / 1 ERROR из 74, причем ошибка — существующий `test_actual_exit_is_timestamped_when_observed_not_at_last_sample` и описанная несовместимость /proc. Этот набор не объявляется зелёным (`capture-regressions.log`).

Pyflakes нового тестового модуля PASS. В product-файле остаётся прежний unused import WprCapture; undefined sqlite3 устранён. Новый импорт не добавляет зависимость.
